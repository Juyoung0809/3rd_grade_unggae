- 페이징은 JPA `Pageable` 대신 기존 `findPublishedCourses()`로 전체 목록을 조회한 뒤 정렬 후 `List.subList()`로 잘라내는 방식을 유지 — 카테고리/키워드 필터와 정렬(평점순/수강생순)이 이미 메모리 상에서 처리되고 있어 일관성을 위해 동일한 방식으로 페이지 분할
- 공통 `PageResponse<T>` DTO를 `common/response` 패키지에 추가해 추후 다른 목록 API에서도 재사용 가능하도록 함
- 레슨 미리보기는 `lecture.preview` 단일 boolean으로 제어하며, `CourseDetailPage`의 잠금 조건을 "첫 번째 레슨만 무료 미리보기"에서 "강사가 지정한 레슨만 미리보기"로 변경 — 비수강생이 미리보기 레슨 클릭 시 별도 모달에서 유튜브 임베드/업로드 영상을 재생
- `/api/admin/**`는 `SecurityConfig`에서 이미 `hasRole("ADMIN")`으로 보호되므로, `AdminStatsService`/`AdminStatsController`는 `AdminUserService`처럼 별도 `checkAdmin()` 호출 없이 구현
- HomePage는 기존 `CourseListPage`의 히어로/카테고리/카드/푸터 스타일을 그대로 재사용하고, 카테고리 바로가기는 `/courses?category=X`로 이동 — `CourseListPage`가 마운트 시 `category` 쿼리 파라미터를 읽어 초기 필터로 적용하도록 최소한의 연동만 추가

### 생성된 파일

### 수정된 파일
- `Front/index.html` — 토스페이먼츠 v1 SDK 스크립트(`https://js.tosspayments.com/v1/payment`) 추가
- `Front/src/api/payments.ts` — `confirmTossPayment(paymentKey, orderId, amount)` 추가 (`POST /api/payments/toss/confirm` 호출)
- `Front/src/pages/PaymentPage.tsx` — "다음" 클릭 시 기존 `preparePayment` → `confirmMockPayment` mock 흐름을 `preparePayment` → `window.TossPayments(clientKey).requestPayment(method, {...})`로 교체. 결제수단 선택값을 토스 SDK의 한글 메서드명(`카드`/`카카오페이`/`토스페이`/`네이버페이`/`계좌이체`/`휴대폰`)으로 매핑(`TOSS_METHOD_MAP`), `successUrl`/`failUrl`에 `courseId` 쿼리 포함
- `Front/src/pages/PaymentSuccessPage.tsx` — 리다이렉트된 `paymentKey`/`orderId`/`amount`로 `confirmTossPayment`를 호출해 결제를 최종 확정, 로딩/성공/실패 상태별 UI 표시
- `Front/src/pages/PaymentFailPage.tsx` — "다시 시도하기" 버튼이 `navigate(-2)` 대신 `courseId` 쿼리로 `/payment/:courseId`로 이동하도록 수정
- `Front/src/App.tsx` — `/payment/success`, `/payment/fail` 라우트 추가 (PrivateRoute)

### 설계 결정
- 토스페이먼츠 v1 SDK(`TossPayments(clientKey).requestPayment(method, options)`)를 사용 — 결제수단 한글 문자열(`카드`, `카카오페이` 등)이 기존 결제수단 선택 UI 라벨과 자연스럽게 매핑됨
- `requestPayment()` 성공 시 브라우저가 토스 결제창으로 리다이렉트되므로, 실제 결제 확정(`confirm`)은 `successUrl`로 돌아온 `PaymentSuccessPage`에서 처리. 기존에 라우팅만 있고 미사용이던 `PaymentSuccessPage`/`PaymentFailPage`를 실제 흐름에 연결
- `VITE_TOSS_CLIENT_KEY`는 `.env`(루트, `envDir: '..'`)의 기존 값을 그대로 사용 — 실제 결제 테스트를 위해서는 토스페이먼츠 개발자센터에서 발급한 테스트 클라이언트 키로 교체 필요
- `confirmMockPayment`(mock-confirm)은 백엔드 엔드포인트와 함께 그대로 보존 (개발/테스트용)

### 설계 결정
- **적용 범위**: 유튜브 임베드와 업로드(`<video>`) 영상 모두 동일한 커스텀 컨트롤 UI를 사용하도록 통일 — 두 영상 타입 간 조작 경험과 진도율 보호 정책(아래)을 일관되게 적용
- **유튜브 자체 컨트롤 차단**: 임베드 URL에 `controls=0&disablekb=1&fs=0`을 추가해 유튜브 기본 컨트롤바/키보드 단축키/전체화면 버튼을 숨기고, iframe 위에 `pointer-events: none`을 적용한 뒤 투명 오버레이 `<div>`를 덮어 iframe으로 가는 클릭/더블클릭/우클릭 자체를 차단. 업로드 영상은 `controls` 속성을 제거하고 동일한 오버레이를 사용
- **배속(재생 속도) 잠금**: 커스텀 컨트롤 UI에 배속 변경 버튼을 두지 않음(유튜브는 `setPlaybackRate`를 호출하지 않아 1배속 유지, 업로드 영상은 `onRateChange`에서 `playbackRate !== 1`이면 강제로 1로 되돌림)
- **"본 구간까지만 자유 이동" 진도율 보호**: 강의별로 `maxWatchedTime`(시청한 최대 시점)을 추적하여, 진행률 바 클릭/드래그 시 탐색 가능한 범위를 `[0, maxWatchedTime]`으로 제한. 되돌려보기는 자유롭게 허용하고, 아직 보지 않은 구간으로의 건너뛰기만 차단. 유튜브는 `setInterval` + `getCurrentTime()` 폴링(500ms)으로, 업로드 영상은 `onTimeUpdate`/`onSeeking` 이벤트로 처리. 이미 완료한 강의(`completed=true`)는 `maxWatchedTime`을 `Infinity`로 시작해 전체 구간 자유 탐색 허용
- **컴포넌트 분리**: 유튜브 플레이어 생성/폴링/이벤트 로직과 컨트롤 UI를 `LessonPlayerPage`에서 `CourseVideoPlayer`로 분리하고, 부모가 `key={lecture.id}`로 강의 전환 시 전체 재마운트시키도록 하여 강의별 상태(재생 위치, maxWatchedTime 등)를 별도 리셋 로직 없이 초기화
- 영상 종료 감지(유튜브 `onStateChange ENDED`, 업로드 `<video onEnded>`)는 기존과 동일하게 부모의 `onEnded` 콜백(`handleVideoEndedRef.current` → `completeLecture` API)을 호출하도록 유지
- **유튜브 일시정지 시 자체 추천영상/채널정보 오버레이 차단**: `controls=0`으로도 유튜브 플레이어가 일시정지·종료·시작전 상태에서 그리는 채널 정보/추천영상/공유 등 자체 오버레이 카드는 cross-origin iframe 내부 UI라 숨길 수 없음. `!playing`일 때 유튜브 영상이면 iframe 전체를 불투명한 검은 레이어(`bg-black`)로 덮어 그 아래 유튜브 UI를 통째로 가리고 자체 재생 버튼만 노출 (업로드 영상은 정지 프레임을 그대로 보여주므로 미적용)
- **진행률 바 드래그 시 동일 지점 반복 탐색으로 인한 오디오 반복재생("아- 아- 아-") 수정**: 시청 한계(`maxWatchedTime`)를 넘어 드래그하면 `seekTo` 대상이 매 `pointermove`마다 동일한 한계 지점으로 클램프되어 `player.seekTo()`/`video.currentTime`이 같은 위치로 반복 호출됨 → 같은 지점으로의 오디오 seek가 반복되며 재생이 끊겨 들림. `lastSeekRef`로 마지막 탐색 지점을 기억해, 클램프된 목표가 이전과 거의 동일(0.1초 이내)하면 실제 seek 호출을 건너뛰도록 수정
- **유튜브 오버레이 차단 재발 수정 (덮기 → 숨기기 + 상태 동기화 원인 제거)**: `bg-black` 오버레이 div로 iframe을 "덮는" 방식은 일시정지 직후 유튜브가 비동기로 보내는 `onStateChange`의 `PLAYING` 이벤트가 우리 `playing` 상태를 다시 `true`로 되돌려 커버 자체가 사라지는 경우가 있어 추천영상/채널정보 카드가 다시 노출되고, 동시에 자체 일시정지 화면(재생 버튼)도 보이지 않는 문제로 이어졌음. ① `onStateChange`에서 `PLAYING`/`PAUSED` 분기를 제거하고 `ENDED`만 처리(재생/일시정지 상태는 `togglePlay`가 단독으로 관리), ② iframe을 가리는 대신 `!playing`일 때 iframe 자체를 `opacity-0`으로 숨겨 컨테이너의 `bg-black` 배경이 그대로 드러나도록 변경(`!playing` 커버 div의 `bg-black` 조건 제거) — z-index/스태킹 순서와 무관하게 유튜브 자체 오버레이를 완전히 비표시 처리
